# R2 업로드 서버 운영 안내

데스크톱 앱은 `https://region-studio-beta.umirr.workers.dev/upload`로 검토·동의 후 생성한 ZIP을 보냅니다. R2 버킷은 `region-studio-beta`, Worker 바인딩 이름은 `SUBMISSIONS`입니다. 버킷의 공개 액세스는 꺼 두세요.

## 배포

GitHub Actions의 **Deploy R2 upload server**가 `main`의 `cloud/**` 또는 배포 워크플로 변경 때 실행됩니다. 다른 브랜치와 PR에서는 배포하지 않습니다. 수동 실행도 `main`만 허용합니다. 동일 서버의 배포는 순서대로 실행됩니다.

저장소 Settings → Secrets and variables → Actions에 다음 두 비밀을 설정합니다. 실제 값은 소스나 이슈에 적지 않습니다.

| 이름 | 내용 |
| --- | --- |
| `CLOUDFLARE_API_TOKEN` | 해당 Cloudflare 계정에만 한정한 Workers 스크립트 편집 + Workers R2 저장 공간 편집 토큰 |
| `INVITE_SHA256` | 베타 초대 코드의 SHA-256 소문자 64자리 해시 |

원본 초대 코드는 운영자가 참가자에게 별도로 전달합니다. API 토큰은 참가자에게 전달하거나 앱에 넣지 않습니다. 이 계정 권한은 계정 안의 Workers/R2 리소스에 적용되므로 토큰을 안전하게 관리하세요. KV, D1, Queues, 영역 편집 등은 필요하지 않습니다.

배포는 설정 검증(`wrangler deploy --dry-run`) → 서버 배포 → 초대 코드 해시 적용 → `/health`의 `configured: true` 확인 순서입니다. 서버 소스만 바뀌면 데스크톱 재설치 없이 반영됩니다. 실패한 실행은 GitHub Actions 로그를 확인하세요.

## 실제 업로드 점검

수동 Run workflow의 **Run live upload test**는 최초 개통 또는 점검 시간에만 켭니다. 자동 배포에서는 꺼져 있습니다. 테스트 동안 운영용 초대 코드가 잠시 작동하지 않으므로 참가자가 업로드 중일 때는 실행하지 마세요.

테스트는 임시 초대 코드를 메모리에서 생성하여 빈 ZIP을 전송합니다. 새 저장 201, 같은 제출 재시도 200, 잘못된 코드 401, 공개 다운로드 404를 검사합니다. 임시 ZIP은 해당 UUID 경로만 삭제하고 운영용 해시를 복원합니다. 사용자 그림은 테스트에 사용하지 않습니다. 실패·취소 시에도 복원 단계를 실행합니다. 강제 종료 등으로 복원까지 실패하면 워크플로를 테스트 옵션 없이 다시 실행하세요.

## 제출 자료 받기

Cloudflare 대시보드 → R2 → `region-studio-beta` → `submissions/`에서 제출 ID와 일치하는 ZIP을 찾습니다. 운영자 권한으로 다운로드한 뒤 `manifest.json`의 동의와 출처, 최종 마스크 품질을 확인하세요. 수집 자료를 공개 GitHub에 커밋하지 마세요.

업로드된 파일은 자동 학습되지 않습니다. 데이터 검수·학습/평가 분할·별도 모델 학습·성능 평가 후 앱 모델을 업데이트하는 과정이 필요합니다. 상세 절차는 [학습 데이터 제출 안내](../docs/학습-데이터-제출-안내.md)를 참고하세요.

삭제 요청은 제출 ID를 기준으로 해당 ZIP을 확인하여 처리합니다. 베타 모집 전에 보관 기간과 문의 창구를 참가자에게 안내하세요. 초대 코드 교체 시 새 코드의 해시로 GitHub 비밀을 업데이트하고 테스트 옵션 없이 배포한 뒤 참가자에게 새 코드를 전달합니다.
