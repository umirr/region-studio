# 학습 데이터 제출 안내

이 안내는 **앱에서 그림을 수정하는 사람**과 **제출 데이터를 받아 모델을 개선하는 운영자** 모두를 위한 문서입니다.

가장 중요한 점은 **자동 저장, 정답 확정, ZIP 생성, 서버 전송, 모델 학습은 서로 다른 단계**라는 것입니다. 그림을 열거나 브러시를 움직였다는 이유만으로 원본이 전송되거나 모델이 학습되지는 않습니다.

## 1. 전체 흐름

```text
내 PC의 원본 이미지
  → AI 또는 선 영역 채우기로 선택
  → 브러시 추가·제거 / 앵커 수정 / 곡선 보정
  → 최종 마스크 확인
  → 현재 마스크 정답 확정
  → 베타 제출 패키지에서 이미지·레이어 검토
  → 제공 권한과 이용 목적 동의
  → 내 PC에 ZIP 저장
  → 선택적으로 R2 전송 동의 + 초대 코드 + 업로드 버튼
  → 운영자 품질 검토 및 데이터 분할
  → 별도의 모델 학습과 성능 평가
  → 검증된 새 모델을 앱 업데이트로 배포
```

**현재 배포 상태:** [Windows 0.8.0 Beta](https://github.com/umirr/region-studio/releases/tag/v0.8.0)와 R2 업로드 서버를 배포했습니다. 테스트 ZIP으로 실제 저장, 동일 제출 재시도, 잘못된 초대 코드 거부, 공개 다운로드 차단을 검증했습니다. 앱에서 서버에 보내려면 초대 코드 입력과 별도 전송 동의, 업로드 버튼 클릭이 필요합니다. 로컬 작업·정답 확정·ZIP 생성만으로 전송되지 않습니다. 운영자는 [R2 서버 운영 안내](../cloud/README.md)를 함께 읽어 주세요.

## 2. 브러시로 고친 영역도 학습에 포함되나요?

**네. 정답 확정한 뒤 제출에 포함한 최종 마스크가 기준입니다.** AI가 처음 선택한 결과보다 사람이 수정한 최종 경계가 정답 데이터입니다.

- 브러시 추가: 최종 마스크에 추가됩니다.
- 브러시 제거: 최종 마스크에서 제외됩니다.
- 곡선 보정: 보정 후의 최종 마스크에 반영됩니다.
- AI를 쓰지 않고 브러시나 선 채우기만 사용해도 제출할 수 있습니다.
- AI를 사용했다면 이용 가능한 초기 AI 마스크와 최근 AI 마스크도 최종 마스크와 구별하여 기록합니다.
- 모든 브러시 움직임을 영상처럼 재생하는 데이터는 아닙니다. 최종 마스크와 브러시 사용 횟수 등 이용 가능한 작업 통계가 기록됩니다.

마스크를 다시 수정하면 **정답 확정이 해제**됩니다. 변경한 경계를 다시 확인하고 확정해 주세요. 브러시 수정 후 AI 재인식을 다시 실행하면 해당 레이어 마스크가 다시 만들어지므로, 최종 결과를 확인해야 합니다. 잘못 바뀌었다면 Ctrl+Z로 되돌릴 수 있습니다.

## 3. 이미지 준비와 작업

1. **폴더 열기**에서 원본 이미지 폴더를 선택합니다. 폴더 바로 아래의 PNG/JPG/JPEG/WebP 파일을 읽습니다.
2. 수백 장을 작업한다면 **일괄 분석 준비**를 먼저 실행할 수 있습니다. 이미지 분석 정보를 PC에 저장하며, 자동으로 정답 마스크를 만들거나 학습하지 않습니다.
3. 이미지에서 포함할 부위를 선택하고, 브러시·제외 앵커로 수정합니다. 선이 분명한 영역은 **선 영역 채우기**를 사용할 수 있습니다.
4. **선택 범위 표시**를 켜서 마스크를 보고, 끄면 실제 채색 결과를 확인합니다.
5. 경계가 정확하면 **현재 마스크 정답 확정**을 누릅니다.

가려진 신체 부위를 상상해서 그리지 말고, 화면에 실제로 보이는 영역을 지정해 주세요. 그림체가 달라도 같은 기준을 적용하는 것이 중요합니다. 예를 들어 옷의 주름과 음영을 같은 옷 영역으로 처리할지 미리 기준을 정해 두면 좋습니다.

## 4. 어떤 이미지가 제출되나요?

- 정답 확정 상태인 이미지가 베타 검토 목록에 나타납니다.
- 목록에 나타났다고 자동 선택되지는 않습니다. 제출할 이미지에 직접 체크합니다.
- 각 이미지 안에서 제출할 레이어도 선택할 수 있습니다.
- 비어 있는 마스크는 제출하지 않습니다.
- **스킵한 이미지**는 학습·베타 제출에서 제외됩니다. 스킵 원본은 작업 결과 일괄 저장 때만 최종 폴더에 그대로 복사됩니다.
- 숨긴 레이어와 제출 제외 레이어는 다른 개념입니다. 베타 검토 화면의 체크 상태를 확인해 주세요.

**주의: 한 레이어만 제출하더라도 그 이미지의 전체 원본이 패키지에 포함됩니다.** 마스크 주변만 잘라 보내는 방식이 아닙니다. 원본에 제출하지 않을 정보가 있다면 먼저 별도 사본에서 제거하고 작업하세요.

## 5. 출처·그림체 정보를 적는 방법

### 출처 묶음

같은 제작자·시리즈·제작 조건의 그림은 같은 이름으로 묶습니다. 예: `내그림-연습세트A`, `작가B-허락받은세트`.

이 정보는 비슷한 그림이 학습용과 평가용에 동시에 들어가 성능이 과장되는 것을 막는 데 사용됩니다. 실명이나 연락처를 적을 필요는 없습니다.

### 그림체 특징

형식은 자유롭습니다. `가는 선, 셀 채색, 흰 배경`, `굵은 외곽선, 부드러운 음영`, `복잡한 배경, 낮은 명암 대비`처럼 적어 주세요. 그림체별 오류를 비교하는 데 도움이 됩니다.

### 이미지 제공 근거

직접 제작 / 제공 허락을 받음 / 제공 가능한 생성 이미지 중 실제 상황에 맞는 항목을 선택합니다. 앱의 체크박스가 이용 권한을 대신 만들어 주지는 않습니다.

여러 이미지를 체크한 뒤 **이 정보를 선택한 이미지에 적용**하면 같은 정보를 한꺼번에 입력할 수 있습니다.

## 6. 동의 항목의 차이

| 항목 | 의미 |
| --- | --- |
| 제공 권한 확인 | 선택한 원본과 마스크를 제공할 수 있음을 확인합니다. |
| 오류 분석·품질 평가 | 운영자가 제출 내용을 검토하고 문제를 분석하도록 허용합니다. ZIP 생성에 필요합니다. |
| 모델 학습·개선된 모델 배포 | 선택 사항입니다. 체크하지 않은 데이터는 학습용으로 사용하면 안 됩니다. |
| R2 전송 동의 | 생성한 ZIP을 비공개 R2 저장소로 보내는 별도의 동의입니다. ZIP 생성만으로 전송하지 않습니다. |

이미지의 공개 배포 동의는 받지 않습니다. 공개 GitHub에는 앱 소스와 설치 파일을 올리며, 제출받은 원본 그림과 마스크를 올리는 구조가 아닙니다.

## 7. ZIP 만들기와 실제 서버 제출

1. 검토와 동의를 완료한 뒤 **동의한 내용으로 ZIP 만들기**를 누릅니다.
2. 내 PC의 저장 위치를 지정합니다. 패키지 생성이 끝나면 제출 ID가 표시됩니다.
3. 여기까지는 **로컬 저장**입니다. 서버에는 보내지 않습니다.
4. 운영자가 전달한 베타 초대 코드를 입력하고 R2 전송 동의에 체크합니다.
5. **생성한 ZIP을 R2에 제출**을 누릅니다.
6. **R2 제출 완료**와 제출 ID가 나와야 서버 제출이 성공한 것입니다. 오류 표시가 나오면 성공하지 않은 것으로 취급하세요.

현재 앱 제한은 패키지당 최대 50장, 로컬 ZIP 최대 2GB, R2 전송 ZIP 최대 90 MiB입니다. 파일이 크면 여러 패키지로 나누어 주세요. 마지막 제한은 이 앱의 전송 구현 제한이며 R2 전체 저장 용량 제한이라는 뜻이 아닙니다.

초대 코드는 업로드용입니다. 계정 비밀번호나 R2 관리자 API 키를 입력하는 칸이 아닙니다. 코드가 없는 사람에게 저장소 읽기나 목록 조회를 제공하지 않습니다. 코드를 공개 GitHub 이슈에 올리지 마세요.

## 8. 패키지에 들어가는 파일

```text
manifest.json
README.txt
image-0001/
  image.png
  mask-001-final.png
  mask-001-initial-ai.png   (기록이 있는 경우)
  mask-001-latest-ai.png    (기록이 있는 경우)
  mask-001-geometry.png     (기록이 있는 경우)
image-0002/
  ...
```

- `image.png`: 앱이 읽은 원본 픽셀을 PNG로 다시 저장합니다. 원본 파일의 경로나 이름 대신 패키지 내부 번호를 사용합니다.
- `final`: 사람이 확인한 최종 이진 마스크. 흰색은 포함, 검정은 제외입니다.
- `initial-ai`, `latest-ai`: 이용 가능한 AI 단계 결과입니다. 없는 기록을 만들어 넣지 않습니다.
- `geometry`: 이용 가능한 자동 보정 단계 결과입니다. 최종 수동 수정과 다를 수 있습니다.
- `manifest.json`: 앱·모델 버전, 가명 참가자 ID, 출처 묶음, 그림체, 동의 기록, 파일 SHA-256, 포함·제외 앵커, 이용 가능한 작업 통계 등을 기록합니다.

**흰색/검정 채색 옵션은 정답 마스크의 포함·제외 의미와 별개**입니다. 검정색으로 칠한 영역도 마스크에서는 선택 영역인 흰색으로 내보냅니다.

안티앨리어싱과 8×8 서브픽셀 샘플링과 가우시안 곡선 후보정은 화면 및 채색 결과의 경계 처리입니다. 학습 마스크는 이진 데이터로 유지합니다. 곡선 보정 버튼은 실제 마스크 모양을 바꾸므로 최종 정답에도 반영됩니다.

## 9. 제출 이후 운영자가 해야 할 일

서버에 ZIP이 저장됐다고 바로 학습을 시작하면 안 됩니다.

1. 패키지 무결성과 manifest를 확인합니다. 알 수 없는 ZIP은 격리된 위치에서 경로 탈출·과도한 압축 해제 크기 등을 검증한 뒤 읽습니다.
2. 동의를 확인합니다. 학습 동의가 없는 자료는 품질 분석용으로 분리합니다.
3. 원본과 최종 마스크를 겹쳐 보고 경계 오류, 누락, 잘못된 부위 선택을 검수합니다. 기본 검토 상태는 `pending`입니다.
4. 중복 이미지 해시와 출처 묶음을 함께 묶어 train / validation / test를 나눕니다. 같은 그림의 변형이 평가 세트에 섞이지 않도록 합니다.
5. 그림체·부위·가림·배경 난이도별로 표본을 확인합니다. 쉬운 그림만 많으면 새로운 그림체 성능이 과대평가될 수 있습니다.
6. 별도 학습 환경에서 모델을 학습합니다. 이 앱에는 자동 학습 실행 기능이 없습니다.
7. 기존 모델과 새 모델의 IoU, 경계 정확도, 사람이 고치는 시간, 추론 지연을 비교합니다.
8. 평가를 통과한 모델만 버전을 올려 앱에 배포합니다. 기존 사용자의 앱 모델이 제출 직후 바뀌지는 않습니다.

삭제나 문의가 필요하면 **제출 ID**를 운영자에게 전달해 주세요. 현재 앱에는 서버 자료 삭제 요청을 자동 처리하는 기능이 없습니다. 실제 베타 모집 전 운영자는 보관 기간, 삭제 요청 창구와 처리 기준을 참가자에게 안내해야 합니다.

## 10. 자주 헷갈리는 점

| 질문 | 답변 |
| --- | --- |
| 자동 저장됐으면 제출된 건가요? | 아닙니다. 내 PC 작업 저장입니다. |
| 정답 확정했으면 학습됐나요? | 아닙니다. 제출할 수 있는 정답 상태입니다. |
| ZIP 생성 완료가 업로드 완료인가요? | 아닙니다. R2 제출 완료 표시를 따로 확인합니다. |
| 브러시로만 만든 마스크도 가능한가요? | 가능합니다. 검토·확정 후 제출하세요. |
| 스킵 이미지는 학습되나요? | 제출 대상에서 제외합니다. |
| 파일을 같은 이름으로 교체하면요? | 위치 스캔으로 갱신합니다. 기존 마스크와 캐시를 새 그림에 적용하지 않습니다. |
| GPT 사용량이 필요한가요? | 앱의 기본 이미지 분석은 로컬 모델로 실행합니다. GPT API를 호출하지 않습니다. |
| 분석 준비와 모델 학습은 같은 건가요? | 아닙니다. 분석 준비는 현재 이미지의 임베딩 캐시 생성입니다. |

기술 구현 위치: `submission.cjs`(패키지), `ui/submission-ui.mjs`(검토·동의 화면), `cloud-upload.cjs`(데스크톱 전송), `cloud/worker.mjs`(R2 수신 서버). 관리 키와 초대 코드는 공개 저장소에 포함하지 않습니다.
